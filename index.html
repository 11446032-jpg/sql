甜品門市訂單與庫存資料庫

資料庫管理實作 - 線上互動 SQL 查詢與分析展示

1. 案例背景

使用者對象：門市店長與庫存管理員。

解決問題：過去門市銷售冰品與甜湯時，品項銷售統計與原料/現貨庫存分散，容易出現熱銷商品缺貨或特定組合無法精確核帳的情況。本資料庫透過標準化關聯結構，串接「商品目錄」、「顧客訂單」及「訂單明細」，協助店長即時掌握銷售額、各品項庫存水位與熱門銷售排行。

2. 資料庫設計 (Schema & ERD)

[products] (商品資料表)
  - id (INTEGER, PK)
  - name (TEXT)
  - price (INTEGER)
  - stock (INTEGER)

[orders] (訂單主表)
  - order_id (INTEGER, PK)
  - order_date (TEXT)
  - payment_method (TEXT)

[order_items] (訂單明細表)
  - item_id (INTEGER, PK)
  - order_id (INTEGER, FK -> orders.order_id)
  - product_id (INTEGER, FK -> products.id)
  - quantity (INTEGER)

4. 查詢結果比較與差異分析

情境：統計每種商品的被訂購次數

查詢 A (使用 INNER JOIN)：

SELECT p.name, COUNT(oi.item_id) AS order_count
FROM products p
INNER JOIN order_items oi ON p.id = oi.product_id
GROUP BY p.name;

結果：僅列出有銷售紀錄的品項（例如芋圓刨冰、紅豆湯），完全沒被購買過的冷門品項直接消失。

查詢 B (修改為 LEFT JOIN)：

SELECT p.name, COUNT(oi.item_id) AS order_count
FROM products p
LEFT JOIN order_items oi ON p.id = oi.product_id
GROUP BY p.name;

結果：列出所有品項，尚未售出的品項計數會顯示為 0。

原因解析：INNER JOIN 僅保留兩表交集的紀錄；若商品在 order_items 內無配對鍵值則會被排除。改用 LEFT JOIN 以商品表（左表）為基準，即使右表無關聯數據也會保留主表資料並以 NULL 填補，經 COUNT(oi.item_id) 計算即能呈現 0，避免庫存統計漏失滯銷品。
